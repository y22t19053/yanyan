# 验言 · 占卜话术质检

> 一个看占卜师是不是在**敷衍你、PUA 你、乱说**的小工具。
> 不判断占卜本身灵不灵，只判断**话术结构**——因为话术是可以结构化判别的，灵验不是。

把一段占卜对话（塔罗、八字、星盘、通灵……都行）丢进来，它给你六维分数、最该注意的几处原文、以及三条你可以问回去的反问。

## 为什么做这个

市面上的占卜质检几乎只有两种：要么是**占卜师互相吹捧的同行评价**，要么是**无差别骂占卜的反对派**。两者都没用——前者永远不会说同行的坏话，后者不管你占得对不对先骂一顿。

这个工具的立场是第三种：**不站队，只看话术结构**。「你身上有东西」是结构问题（无法验证的恐吓），「你这个月工作容易反复」是内容问题（可能对可能错）。工具只判前者，不碰后者。

规则来自一位占卜师本人整理的 734 行经验档案（`浮生牌_经验注入/01_占卜经验档案.md`）——他知道同行哪句话是真在帮忙、哪句话是在做生意。

## 它怎么判

两层结构，刻意分开：

### 第一层 · 确定性扫描（`scan.py`，零依赖）

只认词表和计数，不调用任何模型。判六维里能用规则判定的五维：

| 维度 | 判的是什么 | 怎么算 |
|---|---|---|
| 含糊度 | 这句话能不能套在任何人身上 | 命中巴纳姆词且无具体锚点 |
| 落地度 | 有没有时间、数字、可执行动作 | 锚点占比 |
| 吓唬-卖药 | 先制造灾难再卖解法 | 三环判定（恐吓→解药→依赖） |
| 依赖度 | 让你离不开他 | 命中依赖诱导词 |
| 复读机 | 把你的话还给你当灵验 | 命中钓鱼句 + 回音检测 |

第六维「牌对不对」需要牌面数据，规则层只做粗筛。

### 第二层 · LLM 判官（`judge.py`，可选）

规则看不出语境。同一句「这个必须尽快处理」，前面是「你身上有东西」就是恐吓营销，前面是「你这份工作已经拖了三个月」就是正常建议。

判官层把规则结果和原文一起喂给本地模型，让它判**真正的判决**、写**人话总结**、给**三条反问**。默认连本机 Ollama，没模型也能跑（`--rule-only`）。

## 装

零依赖。只要 Python 3.8+：

```powershell
git clone https://github.com/y22t19053/yanyan.git
cd yanyan
python scan.py examples/demo_chat.txt
```

要用判官层，装一个本地模型即可（不需要联网，不需要 API key）：

```powershell
# Windows
winget install Ollama.Ollama
ollama pull qwen3-8b-q4
ollama serve   # 另开一个窗口

python judge.py examples/demo_chat.txt
```

也支持任何 OpenAI 兼容端点：

```powershell
python judge.py examples/demo_chat.txt --backend openai --base-url http://localhost:8000/v1
```

## 用

输入是一段对话文本，UTF-8。用「占卜师：」「我：」开头能提高角色识别准确率，没有也能跑（按全量评估，报告里会标注）。

```powershell
# 纯规则扫描，最快
python scan.py 我的对话.txt

# 带 JSON 输出
python scan.py 我的对话.txt --json out.json

# 交给本地模型判
python judge.py 我的对话.txt --out 报告.md

# 指定牌面，启用牌义粗筛
python judge.py 我的对话.txt --cards "愚者,塔,月亮"

# 没有模型也能出报告（用规则命中顶上）
python judge.py 我的对话.txt --rule-only
```

## 输出长什么样

```markdown
# 验言 · 话术质检报告

**文件**　examples/demo_chat.txt
**判决**　**操控**（六维均值 31）

> 用恐吓+解药链条诱导付费，专业度极低

## 最该注意的三处
1. 第10行：「你祖上可能有业障，因果缠身」——制造灾难，恐吓用户
2. 第13行：「需要供养，一千八百块，点灯连续做七天」——直接推销高价服务
3. 第15行：「你不要跟别人说，说破了就不灵了」——切断客户获取第三方信息的渠道

## 你可以这样问回去
1. 这个判断是从哪张牌、哪个盘上看出来的？
2. 如果我不做，你判断会发生什么？依据是什么？
3. 这件事我可以去问别人吗？如果不行，为什么？
```

## 设计原则：误报比漏报更致命

一个把专业占卜师判成骗子的工具，比一个漏掉骗子的工具更没用——前者会让用户不再相信任何判断。

所以这套规则刻意收紧：

- **恐吓-卖药必须成链**。只吓人不卖药，降一级。
- **否定语境排除**。「我不做改运」不会被当成「他在卖改运」。
- **时间锚点要具体**。「近期」「不久的将来」不算落地。
- **空输入报「数据不足」**，不报「干净」。

回归测试里「干净样本不得误判」的断言比「坏人样本必须被抓」更严格，见 `tests/test_scan.py`。

## 局限

- **只判话术，不判对错。** 一个用操控话术讲对了事的占卜师，工具会判他有问题；一个用专业话术讲错了事的，工具会判他干净。这是刻意的——话术可判，对错不可判。
- **牌义基准只有 22 张大阿卡纳**，且是占位版。完整 78 张需要接入公开数据集。
- **中文为主。** 词表是中文的，角色解析也按中文习惯写的。其他语言要换词表。
- **规则层会漏。** 真正的判决要靠 L2，规则层只是给它铺路。

## 规则文件

| 文件 | 作用 |
|---|---|
| `rules/巴纳姆词表.md` | 万能句、钓鱼句、正确废话、模糊时间 |
| `rules/恐吓-解药链.md` | 三环判定：恐吓词 / 解药 / 依赖诱导 |
| `rules/六维评分卡.md` | 维度定义、公式、总判决表 |
| `rules/牌义基准.json` | 大阿卡纳 22 张的核心含义与常见误用 |

规则文件全是 Markdown / JSON，改了不用动代码。
